# Мониторинг системы распознавания лиц

## Технические метрики

### 1. Latency (Prometheus + Grafana)
- **P50/P95/P99 pipeline latency:** от кадра до решения
- **По компонентам:** детекция → качество → liveness → эмбеддинг → поиск → решение
- **Цели:** P95 < 1 секунда, P99 < 2 секунды
- **Алерты:** P95 > 1.5 секунды более 5 минут

### 2. Доступность
- **Камеры:** uptime, FPS, разрешение
- **Edge-узлы:** CPU/GPU/память, температура
- **Сеть:** latency до центрального сервиса, packet loss
- **Турникеты:** статус, ошибки команд
- **Целевая доступность:** 99.9% (8.76 часов downtime/год)

### 3. Ошибки интеграции
- **Failed commands к турникетам:** процент отказов
- **API ошибки центрального сервиса:** 5xx, 4xx
- **Ошибки моделей:** inference failures, OOM
- **Алерты:** error rate > 1% более 2 минут

### 4. Latency поиска по базе
- **Локальный кэш (edge):** P95 < 50 мс
- **Центральная база:** P95 < 200 мс
- **Cache hit rate:** цель > 80%
- **Алерты:** cache hit rate < 60% или latency > цели

## ML метрики

### 1. False Reject Rate (FRR)
- **Расчёт:** denial событий / общее число попыток сотрудников
- **Цель:** < 5% в rolling 24h window
- **Детализация:** по проходным, по времени суток, по условиям освещения
- **Действие при превышении:** пересмотр порогов, проверка качества камер

### 2. Доля ручных проверок
- **Расчёт:** manual_review / (allow + manual_review + deny)
- **Цель:** < 15% в rolling 24h window
- **Анализ причин:** качество кадра vs liveness vs матчинг
- **Действие при превышении:** оптимизация моделей/правил

### 3. Качество кадра
- **Среднее quality_score:** по всем событиям
- **Распределение:** гистограмма quality_score
- **Доля low-quality:** quality_score < 0.7
- **Корреляция:** качество кадра vs FRR
- **Действие:** калибровка камер, проверка освещения

### 4. Liveness failures
- **Liveness failure rate:** liveness_score < 0.8
- **По типам:** фото, видео, маска
- **Детекция новых атак:** outlier detection в liveness features
- **Действие:** обновление liveness модели при новых атаках

### 5. Drift входящих кадров
- **Feature drift:** распределение эмбеддингов, quality_score
- **Covariate shift:** освещение, ракурсы, сезонность
- **Методы:** KL-divergence, PSI (Population Stability Index)
- **Алерты:** PSI > 0.1 за неделю
- **Действие:** адаптация моделей, сбор новых данных

## Бизнес метрики (из product.md)

1. **North Star:** Доля автоматических проходов ≤1 секунда без false accept > 90%
2. **Время прохода:** среднее, P95, по проходным
3. **Нагрузка на охрану:** число ручных проверок/час
4. **Экономический эффект:** расчёт по формуле из product.md

## Стартовые алерты (Day 1)

### Critical (PagerDuty)
1. **False accept detected:** любой подтверждённый false accept
2. **System unavailable:** все проходные недоступны > 5 минут
3. **Security breach:** попытка обхода системы

### Warning (Slack)
1. **High latency:** P95 > 1.5 секунды более 5 минут
2. **High FRR:** > 10% более 1 часа
3. **High manual review:** > 25% более 2 часов
4. **Camera failure:** камера offline > 10 минут
5. **Model drift:** PSI > 0.2 за неделю

## Дифференциация сбоев vs деградации модели

### Сбой камеры/освещения
- **Признаки:** резкое падение quality_score на одной камере
- **Метрики:** яркость, контраст, FPS
- **Диагностика:** сравнение с историческими значениями этой камеры
- **Действие:** проверка оборудования, temporary порог adjustment

### Деградация модели
- **Признаки:** постепенный рост FRR на всех камерах
- **Метрики:** accuracy на hold-out validation set
- **Диагностика:** A/B тест со старой моделью
- **Действие:** retraining, проверка feature drift

### Изменение условий
- **Признаки:** сезонные изменения (зима/лето, утро/вечер)
- **Метрики:** распределение quality_score по времени
- **Диагностика:** анализ трендов, сравнение с прошлым годом
- **Действие:** адаптивные пороги, сезонные модели

## Мониторинг по проходным и камерам

### Дашборды
1. **Глобальный:** все проходные, ключевые метрики
2. **Per-gate:** детализация по каждой проходной
3. **Per-camera:** детализация по каждой камере
4. **ML-centric:** метрики качества моделей

### Сравнение
- **Benchmarking:** проходные друг с другом
- **Тренды:** день к дню, неделя к неделе
- **Аномалии:** отклонение от expected patterns

### Root cause analysis
- **Drill-down:** глобальная метрика → проходная → камера → событие
- **Correlation:** метрики между собой (latency vs quality)
- **Временные паттерны:** по часам, дням недели

## Расследование событий доступа через audit trail

### Полный аудит
1. **Event ID → все данные:**
   - Исходный кадр (шифрованный)
   - Все промежуточные результаты (детекция, quality, liveness, эмбеддинг)
   - Кандидаты поиска (топ-5 с scores)
   - Решение и причина
   - Логи каждого компонента

2. **Поиск по:**
   - employee_id
   - timestamp range
   - decision type
   - качеству или score thresholds

3. **Визуализация:**
   - Side-by-side: кадр с камеры vs эталон
   - Timeline событий сотрудника
   - Анализ похожих событий (clustering)

### Security incidents
1. **False accept investigation:**
   - Анализ всех этапов pipeline
   - Сравнение с похожими успешными deny
   - Проверка на новые типы spoofing

2. **Pattern detection:**
   - Множественные попытки одного лица
   - Подозрительные временные паттерны
   - Атаки на несколько проходных одновременно

## Отслеживание исходной задачи

### Business Value Monitoring
1. **Проверка гипотез:** A/B тесты из product.md
2. **Экономический эффект:** реальный vs ожидаемый
3. **Satisfaction:** опросы сотрудников и охраны

### Goal-Question-Metric (GQM)
- **Goal:** Ускорить проход сотрудников
- **Question:** Насколько сократилось время прохода?
- **Metric:** P95 времени прохода, доля ≤1 секунда

- **Goal:** Разгрузить охрану
- **Question:** Насколько сократилось число ручных случаев?
- **Metric:** Ручные случаи/день, время обработки/случай

- **Goal:** Повысить безопасность
- **Question:** Не повысился ли false accept rate?
- **Metric:** Подтверждённые false accept, security incidents

### Feedback loops
1. **От охраны:** качество UI для ручной проверки
2. **От сотрудников:** жалобы на отказы/задержки
3. **От эксплуатации:** стабильность, простота управления
4. **В ML pipeline:** delayed labels для retraining
