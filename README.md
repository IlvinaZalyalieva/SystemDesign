# Face Recognition Access Control System

Система распознавания лиц для автоматического контроля доступа на проходных офисного кампуса. Система обрабатывает кадры с камер, идентифицирует сотрудников и принимает решение о доступе с ручным контролем охраны для сомнительных случаев.

## Ценность для бизнеса

Система ускоряет проход сотрудников в пиковые часы, снижая время ожидания с 90+ секунд до 1 секунды. Это экономит до 45% времени сотрудников в утренние/вечерние пики и разгружает охрану на 40 ручных случаев в день. Автоматизация уменьшает потери от утерянных карт (300 карт/год) и предотвращает передачу карт. 

## Как запустить PoC

### Способ 1: Основная демонстрация (рекомендуется)
```bash
# Демонстрация обоих сценариев:
python3 src/demo_fixed.py

# Или через оригинальный скрипт (менее стабильный из-за mock данных)
python3 src/demo.py
```

### Способ 2: Демонстрационный скрипт
```bash
# Делаем скрипт исполняемым
chmod +x run_demo.sh

# Запускаем демо
./run_demo.sh
```

### Способ 3: API сервер
```bash
# Запуск FastAPI сервера
python3 src/api/main.py

# API будет доступен по адресу: http://localhost:8000
# Документация API: http://localhost:8000/docs
```

### Способ 4: Тестирование
```bash
# Smoke test для проверки работоспособности
python3 test_smoke.py
```

PoC демонстрирует:
1. **Happy path**: обнаружение лица, проверка качества, метчинг с базой сотрудников, принятие решения
2. **Risky path**: низкое качество кадра, метчинг, решение с учётом всех факторов
3. **Логирование**: все события записываются в логи с детальными причинами решений
4. **Mock компоненты**: face detection, quality assessment, liveness checking, face matching
5. **Правила принятия решений**: система порогов для allow/deny/manual_review

## Архитектура

**Реализовано в PoC:**
- Детекция лиц с использованием OpenCV и MTCNN
- Mock-проверка liveness
- Mock-база эмбеддингов сотрудников
- Правила принятия решений с порогами
- Логирование событий доступа

**Архитектурный дизайн (не реализовано в PoC):**
- Гибридная архитектура: инференс на edge, база эмбеддингов в центре
- ANN-индекс для поиска one-to-many в реальном времени
- Деградация при потере сети
- Асинхронная синхронизация с центральной системой
- Полноценный интерфейс для ручной проверки охраной

## Используемые модели и библиотеки

- **Face detection**: MTCNN (или RetinaFace для production)
- **Face recognition**: ArcFace/AdaFace эмбеддинги
- **Liveness detection**: комбинация правил (моргание, движение) и модели
- **ANN search**: FAISS или ScaNN для поиска в больших базах

## Допущения и ограничения MVP

1. Используются mock-эмбеддинги вместо реальных данных сотрудников
2. Liveness проверяется по правилам (не ML модель)
3. Нет реальной интеграции с турникетами
4. База сотрудников ограничена 10 demo-записями
5. Нет обработки офлайн-режима и синхронизации

## Риски, не закрытые в MVP

1. Юридические вопросы обработки биометрических данных
2. Защита от сложных spoofing атак
3. Масштабирование до сотен тысяч записей
4. Реальная деградация при сбоях сети
5. Производительность на реальном edge-оборудовании
