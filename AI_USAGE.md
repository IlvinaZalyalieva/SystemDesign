# Использование AI-инструментов в проекте

## Обзор использования

AI использовался на всех этапах работы над проектом системы распознавания лиц в качестве помощника:

1. **Понимание задачи и декомпозиция** - анализ технического задания, выделение ключевых требований и ограничений
2. **Проектирование архитектуры** - разработка компонентной модели, выбор технологий, проектирование потоков данных
3. **Выбор CV/ML-подходов** - анализ методов распознавания лиц, liveness detection, поиска в больших базах
4. **Разработка PoC** - написание кода компонентов, интеграция, создание демо-сценариев
5. **Написание документации** - создание технической и продуктовой документации
6. **Поиск рисков и ограничений** - анализ edge cases, security considerations, operational aspects

## Инструменты и их роль

### 1. Анализ и проектирование
- **Роль AI:** Помог декомпозировать сложную задачу на компоненты, предложил архитектурные паттерны для low-latency систем
- **Ключевые решения кандидата:** Выбор гибридной архитектуры (edge + cloud), определение порогов принятия решений, расчёт экономического эффекта
- **Отклонения от AI предложений:** AI предлагал более сложную MLOps инфраструктуру, но для MVP была выбрана упрощённая версия

### 2. Выбор CV/ML подходов
- **Роль AI:** Предоставил обзор state-of-the-art методов face recognition, сравнил MTCNN vs RetinaFace, ArcFace vs AdaFace
- **Ключевые решения кандидата:** Выбор готовых моделей для MVP с возможностью дообучения, комбинация правил и моделей для liveness
- **Отклонения от AI предложений:** AI предлагал обучать модели с нуля, но для ограниченного времени выбраны предобученные модели

### 3. Разработка PoC
- **Роль AI:** Генерация структуры кода, написание boilerplate, реализация mock компонентов
- **Ключевые решения кандидата:** Фокус на двух ключевых сценариях (happy path и risky path), создание реалистичных mock данных
- **Самостоятельные решения:** Логика принятия решений с тремя исходами (allow/deny/manual_review), система порогов, обработка edge cases

### 4. Документация
- **Роль AI:** Помог структурировать документацию, предложил шаблоны для разных артефактов
- **Ключевые решения кандидата:** Адаптация документации под конкретные требования задания, добавление продуктовых расчётов, создание диаграмм архитектуры
- **Отклонения от AI предложений:** AI предлагал более общие формулировки, но были добавлены специфичные для задачи детали

## Примеры ошибок AI и их исправление

### 1. Неверные архитектурные предположения
**Ошибка AI:** Предлагал полностью централизованную архитектуру с передачей всех кадров в облако
**Исправление:** Реализована гибридная архитектура с edge вычислениями для достижения <1 секунды latency
**Как обнаружили:** Анализ требований по latency и работе в offline режиме

### 2. Небезопасные рекомендации
**Ошибка AI:** Предлагал хранить исходные изображения лиц неограниченное время
**Исправление:** Реализовано ограниченное хранение изображений (30 дней) и постоянное хранение только эмбеддингов
**Как обнаружили:** Анализ privacy requirements и регуляторных ограничений по биометрическим данным

### 3. Нерабочий код
**Ошибка AI:** Предложил использовать библиотеку insightface без учёта требований CUDA
**Исправление:** Использованы mock эмбеддинги для демо с возможностью замены на реальные модели
**Как обнаружили:** Тестирование в окружении без GPU, анализ зависимостей

### 4. Пропущенные риски
**Ошибка AI:** Не учитывал risk of tailgating и double access
**Исправление:** Добавлены правила для предотвращения двойного открытия, временные окна между проходами
**Как обнаружили:** Анализ security requirements, brainstroming edge cases

### 5. Слишком общие ответы
**Ошибка AI:** Давал общие рекомендации по monitoring без конкретных метрик
**Исправление:** Разработаны конкретные метрики для каждого компонента, пороги для алертов
**Как обнаружили:** Требование задания по конкретным monitoring metrics

## Проверка безопасности при работе с биометрией

Для проверки, что AI не предлагает небезопасный дизайн:

1. **Принцип минимальных привилегий:** Проверка всех рекомендаций на соответствие - хранить только необходимые данные
2. **Data minimization:** Критическая оценка каждого предложения по хранению данных
3. **Privacy by design:** Добавление шифрования, access control, audit logging даже если AI не предлагал
4. **Регуляторная проверка:** Сравнение с GDPR, российскими законами о персональных данных
5. **Security review:** Анализ каждого компонента на уязвимости (model inversion, spoofing attacks)

## Измерения в решении после работы с AI

1. **Упрощение MLOps:** Изначально AI предлагал сложный pipeline
2. **Добавление degraded mode:** AI не учитывал работу при потере сети, добавлен offline режим
3. **Уточнение порогов:** AI давал общие рекомендации, пороги уточнены на основе бизнес-требований
4. **Расширение monitoring:** Добавлены бизнес-метрики поверх технических метрик от AI
5. **Улучшение documentation:** Структура документации переработана для лучшей читаемости

## Заключение

AI был эффективным помощником на всех этапах, но ключевые архитектурные и продуктовые решения принимались самостоятельно. Основная ценность AI - ускорение рутинных задач (код generation, поиск информации) и предоставление альтернативных вариантов для рассмотрения. Критическое мышление и domain expertise были необходимы для фильтрации и адаптации AI предложений под конкретные требования задачи.
